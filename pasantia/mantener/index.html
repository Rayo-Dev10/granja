🛠️ Arquitectura en una página

Esta sección es para quien herede el sitio. El objetivo es que pueda mantenerlo, actualizarlo y repararlo sin el autor. Empiece por aquí; las páginas siguientes son el detalle operativo.

Qué es el sitio, en una frase

Un sitio estático: HTML semántico + Tailwind CSS compilado + JavaScript vanilla. Sin frameworks, sin base de datos, sin login, sin backend obligatorio. Se sube por FTP a una carpeta y funciona. Los pequeños trozos de PHP (guardado de correcciones, plantillas, mano de obra) son opcionales: si el hosting no tiene PHP, el sitio sigue mostrándose, solo que sin guardado compartido.

De dónde salen los datos

El sitio no lee el Excel en vivo. Un script de Python (tools/exportar_datos.py) lee el libro con openpyxl, lo normaliza y escribe seis archivos data/*.js, cada uno con una sola asignación global (window.DATA_XXX = {...}). Las páginas cargan esos .js con etiquetas <script> y, a partir de ahí, todo se calcula en el navegador: KPIs, gráficos SVG dibujados a mano y los 36 controles de coherencia.

El único punto de contacto entre el Excel y el sitio son esos seis data/*.js. Actualizar el sitio = regenerarlos y volver a subirlos. Nada más cambia.

⚠️ El orden de carga de los <script> es obligatorio

En cada HTML: primero los data/*.js, luego js/util.js, luego el resto de js/, y de último el módulo de la página. Poner js/ antes que data/ deja la página en blanco.
